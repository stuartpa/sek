# SpecExplorerKit v0.1.4

Bounded exploration and fresh, structured proof evidence.

## Highlights

- Exploration shares resource and time budgets and reports incomplete results instead of presenting truncated graphs as proof.
- Strict proof contracts identify the model scope, required cases and rejection obligations. `sek build` records the build attestation required for strict proof.
- Checkpoint reuse requires matching complete exploration and current build evidence; replay is performed again.
- Rejection replay checks the expected exception type and message when specified, and distinguishes invocation setup errors from expected rejections.
- Graph serialization is bounded, and generated tests include the binding assets needed for replay.

Incomplete exploration is diagnostic only and cannot be used as proof. A scoped proof does not establish behavior outside its declared scope. CLI and engine branch coverage remain below the project's readiness bar; this release does not claim that bar has been met.
