# SpecExplorerKit v0.1.3

.NET 10-only repository and modern solution consolidation.

## Highlights

- **Pure .NET 10.** Every active product, component, sample, test, generated-test template,
  package, workflow, document, and Agent Skill now targets or requires .NET 10.
- **Exact SDK pin.** `global.json` pins SDK `10.0.303` with roll-forward disabled.
- **One modern solution.** `Sek.slnx` contains all 21 active projects and is the authoritative
  build/test graph for local development, CI, and release validation.
- **Framework-qualified outputs.** Build and configuration paths use `bin/Debug/net10.0`, avoiding
  cross-target assembly collisions and stale shared intermediates.
- **Legacy build-system removal.** `samples-source/` retains original source and byte-identical Cord
  fixtures for provenance, while obsolete `.sln`, project, test-run, and compiled build artifacts
  are removed.
- **Executable purity gate.** Repository tests reject legacy framework contracts, legacy
  solutions/projects, unqualified Debug output paths, incomplete `Sek.slnx` membership, or
  incorrect workflow/runtime requirements.

## Build and test

```bash
dotnet --version            # 10.0.303
dotnet build Sek.slnx -c Debug
dotnet test Sek.slnx -c Debug --no-build
pwsh scripts/regression.ps1
```

`sek generate` now emits standalone `net10.0` xUnit projects.

## Spec Kit extension

The extension ID remains `sek`, and now requires .NET 10 or later:

```bash
specify extension add sek \
  --from https://github.com/stuartpa/sek/releases/download/v0.1.3/spec-kit-sek.zip
```
